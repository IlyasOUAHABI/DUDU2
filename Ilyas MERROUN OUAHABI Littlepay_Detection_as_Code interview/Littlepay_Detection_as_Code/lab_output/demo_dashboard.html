What the challenge scenarios revealed

Reproducible limitations of the current rule logic—not artificial score adjustments. They point directly to the next improvements.

E24

PAN mistakenly logged under a reference key

The non-card field exclusion hides a genuine PAN (false negative).

Potential improvement Review strict exclusions and combine field context with service-specific evidence.
E25

PAN with unsupported dot separators

An uncommon separator prevents a candidate from being extracted (false negative).

Potential improvement Support additional safe formats and test boundary conditions.
E26

Luhn-valid billing reference

An unlisted business field is mistaken for a PAN (false positive).

Potential improvement Use validated service-specific field maps rather than a global list.
E27

Non-payment configuration security code

An ambiguous non-payment security code triggers a CVC finding (false positive).

Potential improvement Scope CVC rules to relevant services and add contextual checks.
E28

Alternate CVV field naming

An unrecognized field alias hides a CVC exposure (false negative).

Potential improvement Maintain a reviewed field-name dictionary with regression coverage.
